# ADR-0004: قرارداد نام‌گذاری Constraintها و Migrationها

## وضعیت

پذیرفته شده (Accepted)

---

## زمینه (Context)

در پروژه از Alembic برای تولید Migration استفاده می‌شود.

در صورتی که برای Constraintها و Indexها نام مشخصی تعریف نشود، پایگاه داده نام‌های تصادفی تولید می‌کند. این موضوع باعث می‌شود Alembic هنگام تولید Migrationهای بعدی نتواند تغییرات را به‌درستی تشخیص دهد و عملیات Drop یا Alter روی Constraintها دشوارتر شود.

---

## تصمیم (Decision)

تمام Constraintها و Indexها باید نام مشخص و قابل پیش‌بینی داشته باشند.

قرارداد نام‌گذاری پروژه:

| نوع | الگو |
|------|------|
| Primary Key | `pk_<table>` |
| Foreign Key | `fk_<table>_<referenced_table>` |
| Unique Constraint | `uq_<table>_<column>` |
| Check Constraint | `ck_<table>_<rule>` |
| Index | `ix_<table>_<column>` |

نمونه:

```python
CheckConstraint(
    "price >= 0",
    name="ck_ticket_types_price_positive",
)

Index(
    "ix_users_email",
    "email",
)
```

---

## گزینه‌های بررسی‌شده (Alternatives Considered)

| گزینه | مزایا | معایب |
|--------|--------|--------|
| نام‌گذاری صریح | Migrationهای پایدار، خطاهای قابل فهم، قابلیت نگهداری بهتر | نیازمند نوشتن چند خط کد بیشتر |
| نام‌گذاری خودکار دیتابیس | کدنویسی کمتر | نام‌های غیرقابل پیش‌بینی، دشواری در Migrationهای بعدی، Debug سخت‌تر |

---

## پیامدها (Consequences)

### مزایا

- Alembic تغییر Constraintها را به‌درستی تشخیص می‌دهد.
- فایل‌های Migration قابل پیش‌بینی و پایدار هستند.
- خطاهای پایگاه داده نام‌های معنی‌دار دارند.
- نگهداری و دیباگ Schema ساده‌تر می‌شود.

### معایب

- توسعه‌دهندگان باید قرارداد نام‌گذاری را رعایت کنند.

- در PostgreSQL، هنگام استفاده از Enumها، Alembic در بسیاری از موارد Typeهای ایجادشده را هنگام `downgrade()` به‌صورت خودکار حذف نمی‌کند. بنابراین لازم است حذف Typeها به‌صورت دستی انجام شود؛ در غیر این صورت اجرای مجدد Migration با خطای `DuplicateObjectError` مواجه خواهد شد.

نمونه:

```python
def downgrade() -> None:
    op.drop_table("orders")
    op.drop_table("reservations")

    sa.Enum(
        name="reservationstatus"
    ).drop(op.get_bind(), checkfirst=True)

    sa.Enum(
        name="orderstatus"
    ).drop(op.get_bind(), checkfirst=True)
```

استفاده از `checkfirst=True` باعث می‌شود اگر Type از قبل حذف شده باشد، عملیات بدون خطا ادامه پیدا کند.
