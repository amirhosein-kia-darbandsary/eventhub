# ADR-0005: استفاده از RS256 برای امضای JWT

## وضعیت

پذیرفته شده (Accepted)

---

## زمینه (Context)

سامانه از JWT برای احراز هویت کاربران استفاده می‌کند. برای امضای Token دو الگوریتم رایج بررسی شدند:

- HS256
- RS256

در حال حاضر تنها یک سرویس Token تولید می‌کند، اما احتمال اضافه شدن سرویس‌های دیگر برای اعتبارسنجی Token در آینده وجود دارد.

---

## تصمیم (Decision)

از الگوریتم **RS256** برای امضای Access Token و Refresh Token استفاده می‌شود.

کلید خصوصی فقط در سرویس احراز هویت نگهداری می‌شود و سایر سرویس‌ها تنها با استفاده از Public Key اعتبار Token را بررسی می‌کنند.

---

## گزینه‌های بررسی‌شده (Alternatives Considered)

| گزینه | مزایا | معایب |
|--------|--------|--------|
| HS256 | ساده، سریع، نیازمند تنها یک Secret | تمام سرویس‌هایی که Token را Verify می‌کنند باید Secret مشترک داشته باشند. در صورت افشای Secret، هر سرویس قادر به تولید Token معتبر خواهد بود. |
| RS256 | جداسازی کامل عملیات Sign و Verify، مناسب معماری Microservice، امنیت بیشتر در توزیع کلید | مدیریت کلیدهای عمومی و خصوصی کمی پیچیده‌تر است. |

---

## پیامدها (Consequences)

### مزایا

- Private Key فقط در سرویس Authentication نگهداری می‌شود.
- سایر سرویس‌ها تنها به Public Key دسترسی دارند.
- افشای Public Key امکان تولید Token جعلی را ایجاد نمی‌کند.
- مقیاس‌پذیری بیشتر در معماری چندسرویسی.

### معایب

- مدیریت Key Pair نسبت به HS256 پیچیده‌تر است.
- نیاز به فرآیند مناسب برای Rotation کلیدها در آینده وجود دارد.
