# ADR-0003: انتخاب SQLAlchemy 2.0 Async به‌عنوان لایه دسترسی به پایگاه داده

## وضعیت

پذیرفته شده (Accepted)

---

## زمینه (Context)

پروژه نیازمند ویژگی‌های زیر است:

- ارتباط Asynchronous با PostgreSQL
- ORM برای نگاشت مدل‌ها
- پشتیبانی کامل از Migration
- مدیریت Relationshipها
- Type Hinting مناسب
- یک اکوسیستم بالغ و مناسب Production

سه گزینه بررسی شدند:

- SQLAlchemy 2.0 Async
- asyncpg
- SQLModel

---

## تصمیم (Decision)

از **SQLAlchemy 2.0 Async** به همراه اجزای زیر استفاده می‌کنیم:

- AsyncSession
- asyncpg
- Alembic
- Declarative Mapping (`Mapped` و `mapped_column`)

---

## گزینه‌های بررسی‌شده (Alternatives Considered)

| گزینه | مزایا | معایب |
|--------|--------|--------|
| SQLAlchemy 2.0 Async | بالغ، مستندات قوی، پشتیبانی کامل Alembic، ORM قدرتمند، امکان استفاده همزمان از ORM و Core | نسبت به گزینه‌های دیگر Boilerplate بیشتری دارد و یادگیری آن زمان بیشتری می‌برد. |
| asyncpg | سریع‌ترین Driver برای PostgreSQL، سربار بسیار کم | فاقد ORM، تمام Queryها باید دستی نوشته شوند، مدیریت Relationshipها و Migrationها بر عهده برنامه‌نویس است. |
| SQLModel | کدنویسی ساده‌تر، هماهنگی خوب با Pydantic | هنوز نسبت به SQLAlchemy بالغ نیست، امکانات پیشرفته کمتری دارد و برای پروژه‌های پیچیده انتخاب اول محسوب نمی‌شود. |

---

## پیامدها (Consequences)

### مزایا

- استفاده از یک ORM بالغ و امتحان‌شده
- یکپارچگی کامل با Alembic
- امکان استفاده از ORM و SQL خام در کنار هم
- Type Hinting مناسب
- جامعه کاربری بزرگ و مستندات کامل
- مناسب برای پروژه‌های بزرگ و بلندمدت

### معایب

- نسبت به SQLModel کدنویسی بیشتری نیاز دارد.
- یادگیری Session، Transaction و Unit of Work زمان‌برتر است.
