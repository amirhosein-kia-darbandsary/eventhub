# ADR-0007: انتخاب استراتژی Pagination

## وضعیت

Accepted

---

## زمینه

سیستم دارای Endpointهای متعددی برای نمایش لیست داده‌ها است. با افزایش حجم داده‌ها، استفاده از یک روش Pagination ثابت برای تمام موجودیت‌ها تصمیم مناسبی نیست؛ زیرا هر موجودیت رفتار، نرخ رشد و الگوی استفاده متفاوتی دارد.

دو گزینه اصلی مورد بررسی قرار گرفتند:

- Limit/Offset Pagination
- Cursor (Keyset) Pagination

---

## تصمیم

استراتژی Pagination بر اساس ویژگی هر موجودیت انتخاب می‌شود و نه به‌صورت یکسان در کل پروژه.

### Venue

برای موجودیت Venue از Pagination ساده مبتنی بر `limit` استفاده می‌شود.

دلایل:

- Venue یک Reference Data محسوب می‌شود.
- تنها مدیران سیستم امکان ایجاد یا ویرایش Venue را دارند.
- تعداد سالن‌ها محدود است و انتظار رشد بسیار زیاد برای این جدول وجود ندارد.
- هزینه و پیچیدگی Cursor Pagination در این سناریو ارزش افزوده‌ای ایجاد نمی‌کند.

---

### Event

برای موجودیت Event از Cursor (Keyset) Pagination استفاده می‌شود.

مرتب‌سازی بر اساس:

- starts_at
- id

فیلد `id` به عنوان Tie-breaker استفاده می‌شود تا حتی اگر چند Event زمان شروع یکسانی داشته باشند، ترتیب نتایج همواره پایدار و یکتا باقی بماند.

Cursor شامل اطلاعات آخرین رکورد صفحه قبل بوده و به صورت Base64 رمزگذاری می‌شود.

---

## گزینه‌های بررسی‌شده

| گزینه | مزایا | معایب |
|--------|--------|--------|
| Limit/Offset | پیاده‌سازی ساده، مناسب داده‌های کم‌حجم | کاهش کارایی روی داده‌های بزرگ، احتمال Duplicate یا Skip هنگام درج و حذف داده |
| Cursor (Keyset) | کارایی بالا، ترتیب پایدار، مناسب داده‌های بزرگ | پیاده‌سازی پیچیده‌تر، نیاز به Cursor و مرتب‌سازی پایدار |

---

## پیامدها

### مزایا

- هر Endpoint متناسب با ماهیت داده از مناسب‌ترین روش Pagination استفاده می‌کند.
- Eventها روی حجم زیاد داده عملکرد مناسبی خواهند داشت.
- هنگام اضافه یا حذف شدن Eventها بین درخواست‌های متوالی، احتمال تکرار یا از دست رفتن رکوردها از بین می‌رود.
- Venue بدون افزایش پیچیدگی، Pagination ساده و قابل فهمی خواهد داشت.

### معایب

- پروژه از بیش از یک مکانیزم Pagination استفاده می‌کند.
- توسعه‌دهندگان باید با هر دو الگو آشنا باشند.
- پیاده‌سازی Cursor نسبت به Offset پیچیده‌تر است.

---

## نتیجه

Pagination یک تصمیم وابسته به دامنه (Domain Driven Decision) است و باید بر اساس ویژگی‌های هر موجودیت انتخاب شود، نه اینکه یک راهکار ثابت در تمام APIها اعمال گردد.
